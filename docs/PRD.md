# 禅 产品需求文档

版本：v0.5 草案<br>
日期：2026-10-21<br>
项目名：`zen`；应用显示名：禅<br>
来源：用户对阶段性计时、专注声音、结束觉察和自主放弃的需求说明；最新范围为个人自用的 Mac 与 iPhone 应用，采用本地文件存储，文件同步由用户自行处理，暂不考虑 Apple Watch。

## 1. 产品定位

「禅」是一款面向个人自用、覆盖 Mac 与 iPhone 的独立应用，专注于轻量计时与本地时间记录。用户可以不填写任务直接开始专注，在结束后补记这段时间做了什么。记录保存为独立目录中的可读文件，方便日后由用户或 AI 检索、整理和回顾。

核心体验：**一键开始 → 专注 → 结束觉察 → 可靠保存到本地。**

产品保持轻量，以“禅”和关注当下为体验方向。应用提供时间边界和记录，不判断用户是否真正专注；修行的感受由使用者自己体会。

## 2. 已确认需求与建议默认值

### 用户已确认

- 当前只考虑 Mac 与 iPhone，暂不考虑 Apple Watch。开始与主动放弃的操作必须方便；两端具体交付顺序待确认。
- 仅供用户自己使用，以简单、轻量和少维护为优先。
- 采用本地文件存储，Mac 与 iPhone 之间的文件同步由用户自行寻找方案并管理；App 不提供内置云同步或云后端。
- 开始前可选任务；没有选任务时，允许直接开始。
- 一个番茄结束后，没有选任务就手动输入本次专注内容。
- 补记只属于这次专注记录，不自动创建待办任务。
- 专注记录保存在用户选择的本地数据目录，由「禅」独立管理；使用应用无需安装或配置其他笔记软件。
- 文件应方便用户和 AI 后续维护与回顾。
- 应用名称为「禅」，使用 `zen` 作为项目名称和项目目录名。
- 支持专注声音定制，木鱼使用真实器物敲击录音，保留自然音色与余音。默认每 2 秒一声，支持音量和敲击间隔调整；声音内置，离线可用。陪伴声音单选：静音、木鱼、松风、细雨。有声选项在专注期间循环播放，提供统一音量和试听，不做混音。磬声仅用于结束提醒，不属于陪伴声音，也不在开始时播放。结束统一敲磬提醒，提醒音量独立于背景声（默认 65%），在每轮开始时固定。
- 一轮专注不提供暂停续接；用户主动决定放弃时，本轮结束，不记录本轮时间，不生成待补记，也不计入累计。
- 第一版不监听锁屏、休眠、应用切换或用户活动来判断专注状态，也不据此自动暂停或放弃。是否放弃由用户自己决定。
- 界面清淡、有禅意；结束时重在觉察这段时间做了什么。

### 本文提出的第一版默认值

以下是为便于开发给出的方案，可在实现中调整，不视为用户已经逐项确认：

- Mac 端采用原生菜单栏应用，支持全局快捷键；两端的建议分工见第 3 节。
- 专注默认 25 分钟，休息默认 5 分钟；休息与下一轮均手动开始。
- 建议每次专注一个 Markdown 文件，以稳定会话 ID 命名，界面按日展示；减少两端新增记录时改写同一文件的机会。
- “选任务”在第一版表现为选择最近用过的专注名称，不维护待办状态。
- 允许空白保存；跨午夜记录按开始日期归档。
- 倒计时在锁屏、休眠期间仍按原定截止时间流逝；系统恢复执行后校准剩余时间或处理到时，不作专注质量判断。
- 暂不开发刘海显示；用户曾表达兴趣，列入后续候选。

## 3. 目标与范围

### 第一版目标

1. 开始专注无需提前组织任务。
2. 结束后用一句话留下有意义的时间记录。
3. 记录可独立于应用阅读、备份和处理。
4. 已完成记录和补记在重启、写入失败等情况下不会静默丢失；主动放弃则不留记录。

### 第一版不包含

账号、云后端、内置云同步、跨设备计时接力或远程控制、Apple Watch 支持、订阅、完整待办管理、日历排程、网站屏蔽、AI 自动总结、复杂统计与刘海动画。Mac 与 iPhone 均纳入产品范围，具体交付顺序待确认；用户自行管理文件同步与备份。

### 两端分工建议

两端遵循相同规则：直接开始、无暂停续接、主动决定是否放弃、到时后可留下觉察记录。界面针对各设备分别设计，不要求每端拥有相同数量的功能。

| 设备 | 主要场景 | 建议能力 |
| ---- | -------- | -------- |
| Mac | 桌前工作、阅读与整理 | 菜单栏计时、专注声音、文字补记、查看记录、管理本地数据目录 |
| iPhone | 离开电脑后的专注 | 开始与放弃、剩余时间、专注声音、到时提醒、补记和查看记录、访问本地数据目录 |

### 跨端关系与文件同步边界

- 两端各自完成本机计时与保存，不依赖网络或另一台设备在线；不实现同一轮计时的跨端接力与远程控制。
- Mac 与 iPhone 采用相同的可读文件格式。用户自行选择外部工具同步文件，或自行复制文件。
- App 负责读取已经到达本地目录的记录，提供刷新入口；文件同步的传输、时效和冲突解决由用户所选方案负责。
- “已保存”仅表示成功写入当前设备目录，不表示文件已同步至另一台设备。
- 运行中会话、恢复草稿和设备设置仅保存在本机；从另一端到达的记录不会启动计时或触发结束提醒。
- 对本机已发现的外部修改或同 ID 不同内容的冲突，保留现有文件与草稿并提示处理，不静默覆盖；不承诺能防止外部同步工具覆盖尚未被 App 读取的数据。

## 4. 用户流程

### 4.1 首次使用

Mac 端首次打开选择一个独立数据目录，展示文件存放方式。目录取消选择则留在设置引导，不静默写入其他位置。完成选择后显示开始按钮；可直接使用默认时长，无需建立项目或任务。

iPhone 端使用系统允许授权访问的本地数据目录；目录选择、权限恢复及与用户所选外部同步工具的兼容性在实现前验证。App 不引导开通云服务。两端均不要求用户提前建立任务系统。

### 4.2 未选任务直接开始

1. 用户在当前设备点击“开始专注”；Mac 端额外支持菜单栏和全局快捷键。
2. 立即开始倒计时；名称输入不是必填步骤。
3. 结束时停止背景声，敲磬提醒并生成待补记记录。Mac 主动打开本轮补记；iPhone 前台直接展示，后台通过通知进入。
4. 显示简短补记界面：“这段时间做了什么？”
5. 用户输入一句话后保存，或选择“暂不填写”保存为未命名记录；Mac 支持 Enter 保存。记录通过用户自己的方案传到另一端后，可在那里查看或补记。

示例：“修复博客移动端导航”“阅读 SwiftUI 文档”“整理职业选择思路”。

### 4.3 开始前选择名称

菜单栏可展开“最近使用”，选择一个已有名称并开始计时。结束界面预填该名称，用户可以修改或补充备注。名称只用于记录归类，不会生成待办或完成状态。

### 4.4 主动放弃

专注中可主动选择“放弃本次”，立即停止计时和声音，取消本轮提醒，清除本轮运行状态并回到空闲。不生成记录文件或待补记，不计入当天累计，不提供暂停或继续。是否需要放弃完全由用户判断，应用不通过系统事件、应用切换或活动检测代为决定。

放弃只影响当前一轮，其他已完成记录和待补记保持不变。界面不对放弃作惩罚性评价。旧版本已有的放弃记录保留并可手动删除，不计入累计；不批量清理用户文件。已完成、异常中断和待补记记录也可在详情中手动删除；确认后移除对应本地文件和草稿，并更新累计时间。

### 4.5 查看与修改

“今天的记录”展示时间、有效时长、名称和完成状态，并汇总当天有效专注时长，排除旧版本放弃记录。可以修改名称、备注及关联资料，也可以在 Finder 打开数据目录。第一版不提供手工修改计时数据的界面。

## 5. 界面与交互要求

以下菜单栏、快捷键、输入法和窗口焦点要求适用于 Mac。iPhone 采用适合手机的触控界面；具体界面另行细化，两端共同保持清淡、有留白、少打扰。

| 入口     | 必需操作与信息                                                         |
| -------- | ---------------------------------------------------------------------- |
| 菜单栏   | 当前状态和剩余时间；开始、放弃本次；最近名称；今天的记录；设置 |
| 结束补记 | 本次有效时长、内容输入、可选备注、保存、暂不填写；主动放弃不进入补记     |
| 今日记录 | 时间、时长、内容、状态、当日汇总、编辑入口                             |
| 设置     | 数据目录、专注和休息时长、快捷键、声音与通知、开机启动选项             |

- 视觉采用暖白纸色、淡墨色、不完全规则的渐细圆环与轻量线条；输入区弱化边框，主按钮保持清晰可点但不过度醒目。
- 主窗口保留计时、15 / 25 / 45 分钟快捷选择、可留空的预期任务输入和开始按钮；顶部采用轻量文字导航，不重复展示标语、状态文案、操作说明或成功提示。
- 声音入口收在任务输入区域右侧，开始按钮在下方独占一行并与输入区域同宽居中；点击声音入口只直接选择静音、木鱼、松风或细雨；自定义时长、音量、木鱼间隔与休息入口放在设置中。专注中只展示计时、已填写的名称与放弃操作。
- 结束补记默认只显示一个问题、时长、输入框与保存按钮；备注、资料、暂不填写和删除收进“更多”菜单，关闭入口保留。
- 待补记通过“留痕”入口的小圆点提示，不在主页重复放置提示卡片。
- 开始专注从菜单栏至多两次点击；设置快捷键后一次按键组合即可开始。
- 补记只需输入一句话并按 Enter 保存；备注和资料关联默认收起。
- 输入法正在组词时，Enter 用于上屏，不触发保存。
- 专注到时后，Mac 主动唤起主窗口和本轮补记输入框，聚焦正文，输入一句后 Enter 保存（中文输入法组词期间 Enter 仍只上屏）。iPhone 前台直接显示补记，后台点通知定位对应记录。结束提醒不依赖 Mac 通知授权；关闭提醒音仍显示补记，放弃与休息不弹出专注补记。
- 关闭补记窗口不会丢弃记录，菜单栏提示“有待补记记录”。下一次打开可继续填写。
- 可以开始下一次专注而不必完成上一条补记；每条待补记记录独立保存。
- 开始与放弃使用独立的可配置全局快捷键；冲突时明确提示。不提供暂停或继续快捷键。
- 休息不计入有效专注时间；休息结束只提醒，不自动开始下一轮。

## 6. 计时与状态规则

两端均不把锁屏、切换应用、进入后台或设备失联判定为放弃。不监听这些事件判断专注，不妨碍为计时、数据保存和提醒使用必要的系统能力。现有检查点与异常恢复细则主要针对 Mac；移动端正常的后台挂起或系统回收不应直接套用崩溃中断规则，应从已保存的会话与截止时间恢复状态。具体计时、后台声音及提醒能力在实现前按平台验证。

计时会话的状态为：空闲 → 专注中 → 已结束（到时完成、主动放弃或异常中断）。不提供暂停与续接。到时完成或异常中断后进入独立的记录流程：待补记 → 已保存。主动放弃直接回到空闲，不生成记录。待补记状态不阻塞新会话。

| 情况           | 行为                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 正常到时       | 在目标有效时长处停止，生成已完成记录；延迟显示提醒不增加时长                     |
| 主动放弃       | 结束本轮并清除运行状态，不生成记录、不进入补记、不计入累计；不能继续本轮                           |
| 锁屏、休眠或应用切换 | 不监听这些事件作专注判断，不自动暂停或放弃；倒计时按原定截止时间流逝。系统恢复执行后，未到时则继续显示剩余时间，已到时则处理完成，记录时长不超过目标时长 |
| 跨午夜         | 保留完整起止时间，按开始时的本地日期归档                                         |
| 更改时长设置   | 仅影响下一次会话                                                                 |
| 应用重启或崩溃 | 如存在未结束的会话草稿，保留最后检查点并标记异常中断，不恢复为可续接会话；此为技术恢复状态，不代表用户主动放弃 |
| 系统时间被调整 | 计时采用包含系统睡眠时段、不受墙上时间调整影响的连续时间基准；起止日期使用带时区的墙上时间 |

记录时长表示本轮计时经过的时间，不是对实际注意力的测量或认证。正常到时记录目标时长，主动放弃不记录时间，异常中断保留最后检查点时长。内部保留秒级精度，界面显示分钟和秒。新正式记录区分完成与异常中断；旧格式的放弃记录仅为兼容而保留。

## 7. 本地数据约定

### 7.1 目录

Mac 与 iPhone 的数据目录只保存可携带的专注记录；应用设置和恢复草稿留在各自的本机支持目录，不作为跨端文件交换的一部分。iPhone 的目录授权方式在实现前验证。以下为建议目录结构：

```text
ZenData/
└── records/
    └── 2026/
        └── 10/
            └── 2026-10-21/
                └── 81963f2c-371b-469c-a54e-1a4345535c72.md
```

本地正式记录建议以 Markdown 为唯一来源，不同时维护另一份必须手工同步的正式数据库。应用可建立可重建索引；索引损坏不影响记录。

建议采用“每条会话一个文件”，文件名使用稳定 ID，按开始日期放入目录；界面仍按日展示，不需要用户手工整理。该方案减少不同会话之间的文件写入冲突，不自动解决两端同时修改同一会话的问题。文件格式与外部同步服务无关。

### 7.2 记录格式

每个文件保存一条会话，采用固定字段和稳定 ID，正文允许用户直接阅读和编辑。时间采用带偏移量的 ISO 8601 格式。示例中的字段和值是第一版建议协议：

```markdown
---
schema_version: 1
date: 2026-10-21
---

## 10:00 修复博客导航

- id: 81963f2c-371b-469c-a54e-1a4345535c72
- started_at: 2026-10-21T10:00:00+08:00
- ended_at: 2026-10-21T10:25:00+08:00
- target_seconds: 1500
- focused_seconds: 1500
- outcome: completed
- annotation_status: recorded
- label_origin: after_session
- reference:

### 内容

修复博客导航

### 备注

处理了移动端菜单遮挡问题。
```

- `outcome`：新记录使用 `completed`（到时完成）或 `interrupted`（技术异常中断）。保留对旧 `abandoned` 字段的读取兼容；主动放弃不再创建记录。
- `focused_seconds` 表示计时经过的秒数，不表示经过注意力监测验证的专注时间。
- `annotation_status`：`pending`、`recorded`、`skipped`。
- `label_origin`：`before_session`、`after_session`、`none`。
- 内容允许中文和多行文本；实现时定义字段、正文的转义和解析规则，避免正文破坏文件结构。
- 未填写内容时显示“未命名专注”；原始内容保持为空。
- `reference` 可选，保存普通文件路径或 URL。
- 每次会话在开始时生成 ID，恢复、重试和修改沿用同一 ID。

### 7.3 保存与恢复

- 开始、到时结束及输入变化时持久化恢复草稿；运行中至多每 5 秒保存一次时长检查点，补记输入短暂防抖保存。主动放弃时清除本轮运行状态，不创建记录草稿；清除写入失败则提示重试，内存中仍保持结束状态并暂时阻止下一轮。
- 结束时先持久化待补记记录，补记是对同一 ID 的更新；结束提醒失败不影响记录。
- 更新单条记录文件使用同目录临时文件和原子替换，写入成功后再清除对应恢复草稿。
- 写入失败明确显示“未保存”，保留草稿，提供重试和更换目录；成功前不得显示已保存。
- 写入前重新读取目标记录文件；如发现相较编辑开始时已发生外部修改，或无法安全解析，停止覆盖，保留原文件和草稿并提示处理。不得改动其他会话文件。
- 移动目录或权限失效时允许重新选择；更换目录只影响后续写入，不自动迁移历史，界面明确说明。
- 单个设备内避免重复实例写入；重复保存、重启恢复和重试不得产生重复记录。刷新目录时按会话 ID 识别记录；相同 ID、相同内容不重复展示，相同 ID、不同内容保留文件并提示冲突，不自动选一份覆盖。
- 文件刷新只更新历史记录和待补记展示，不影响当前本机会话。外部同步造成的删除传播、版本保留与传输失败由用户所选工具处理。

## 8. 验收标准

下表为当前基础闭环的验收，菜单栏、目录与强制退出细则以 Mac 为基线。两端还需分别验证后台计时、到时提醒与专注声音；正常后台挂起不得自动判为放弃。文件交换只验收本地读写、刷新、去重与可发现的冲突保护，不验收外部同步服务的传输时效，不实现同轮跨端控制。

| 场景       | 通过条件                                                              |
| ---------- | --------------------------------------------------------------------- |
| 空白开始   | 无需名称和任务即可通过菜单栏或快捷键启动                              |
| 正常结束   | 生成一条待补记记录，补记一句后保存，不创建待办                        |
| 预选名称   | 结束时名称预填，修改后写回同一记录                                    |
| 主动放弃   | 专注 8 分钟后主动放弃，停止声音与计时，无记录文件、无待补记、累计不增加；重启不恢复该轮         |
| 自主判断   | 不提供暂停续接，不监听锁屏、休眠、应用切换或用户活动来判断或终止专注 |
| 延后补记   | 关闭窗口和重启应用后，待补记内容仍可恢复；新一轮可以开始              |
| 木鱼声音   | 播放真实木鱼录音，柔化尖锐敲击并加入轻柔空间余韵；默认每 2 秒一声，短间隔下余韵自然叠加；不改变音高，断网仍可播放 |
| 中文输入   | 拼音候选上屏的 Enter 不误提交；中文、换行、特殊符号保存后可还原       |
| 异常恢复   | 强制退出后保留最后检查点并标记异常中断，不出现暂停续接，不标记为主动放弃 |
| 文件失败   | 目录不可写时仍保留记录，恢复权限重试后只有一条记录                    |
| 外部编辑   | 编辑期间目标记录被外部修改时停止覆盖，保留文件与草稿；其他记录文件不受影响 |
| 文件交换   | 将 Mac 生成的记录复制到 iPhone 数据目录（反向亦然），刷新后可读取、补记；不触发计时或结束提醒 |
| 重复与冲突 | 相同 ID、相同内容只展示一条；相同 ID、不同内容保留文件并提示，不静默覆盖 |
| 本地保存   | 无网络也能计时和保存；界面不把本地保存成功显示为同步完成 |
| 跨日与休眠 | 按约定归档；休眠不改变本轮截止时间；恢复执行后校准倒计时，已到时则完成且时长不超过目标 |
| 独立可读   | 无需打开「禅」，即可用文本编辑器阅读和备份全部正式记录         |

## 9. 实现建议与开发顺序

建议使用 Swift 与 SwiftUI 实现 macOS 与 iOS 应用，共享会话规则、文件格式与解析逻辑，按设备设计界面。具体最低系统版本、后台计时、声音、文件访问及提醒 API 在实现前验证，不把技术选型当作已确认的产品需求。

建议先验证 Mac 与 iPhone 对同一记录格式的读写及手机目录授权，再完成两端计时体验。两端具体交付顺序待确认；当前不安排 Apple Watch 或内置同步开发。

1. **计时闭环**：菜单栏、开始/主动放弃、结束补记、单条记录文件保存。
2. **可靠性**：检查点、异常恢复、原子写入、失败重试、去重及外部编辑保护。
3. **日常使用**：全局快捷键、今日记录、最近名称、设置、通知与声音。

完成上述验收后，再考虑刘海展示、跨天统计、按名称汇总、导出及 AI 回顾。第一版成功标准是用户可以连续使用一周，便捷地开始专注并留下可用的时间记录，无需每天维护任务系统。

## 10. 新项目启动说明

将本文件复制到新项目作为 `docs/PRD.md`，按第 9 节从计时闭环开始构建。优先满足不选任务直接开始、结束后补记和独立本地文件保存。实现过程中可以调整建议默认值，但应保留第 2 节用户已确认的需求。不要为第一版引入账号、服务端或完整待办模块。
